# Quire native

The Rust/GPUI rewrite is underway. The default executable hosts Zed's editor and Vim in two panes sharing an in-memory example note. Each pane can switch between Source and Write presentation using the copied Markdown and inline grammars. Existing stored pages support editing, recovery, and local saves. Daily-page navigation and the remaining application workflows are still in [the task queue](plans/native-rewrite-tasks.md).

Open a stored page with its native database and original identities:

```sh
cargo run -p quire --locked -- \
  --notebook-db /path/to/local.sqlite \
  --notebook-id notebook-id --writer-id writer-id --page-id page-id
```

The window loads one selected revision and optional recovery through the storage worker. Concurrent opens within a notebook session share one buffer and analysis model. Recovery takes precedence when opening a page. Conflicts, deleted versions, and missing pages remain read-only until their resolution or creation workflow is available. A recovery draft whose base version is in storage and whose page still lives at the draft's path opens editable and is saved from that base as soon as editing starts, so the store merges it with anything saved since. Other drafts, including those typed into a version this store does not have or moved to another path, open read-only and stay for review. Unrepresentable UTF-16 strings produce an actionable error without creating a lossy buffer. A failed page read can be retried after its cause is corrected; startup failures require reopening the notebook.

Copy Markdown copies the whole page, including recovered text, with its original line endings. It captures the page when clicked and prepares the clipboard contents in the background. The shared source mapping preserves untouched LF, CRLF, and bare-CR endings through native edits and undo; new line breaks use the first opened line-break style, or LF for a page without line breaks.

Typing records recovery after 100 ms of inactivity and saves locally after 450 ms, and no later than 2 s after the first unsaved edit during steady typing. Save locally, Cmd-S on macOS, or Ctrl-S elsewhere saves immediately. Status distinguishes recovery from a committed local save; folder publication remains separate. A save acknowledges its captured version, so later typing stays dirty. If the page changed elsewhere, the save still goes out from the version the editor opened, the store merges both inside the save transaction, and the editor shows the merged text while keeping anything typed during the save. Where both sides changed the same words, both versions are kept and the status names the page. Saving to a page deleted elsewhere restores it; an unchanged page saved from a deleted version stays deleted, and the status says to edit and save to restore it. `PagePersistence::absorb` brings another writer's version into an open page: the edits made since the last saved text merge into it as one buffer edit that keeps cursors and anchors and stays out of undo history. A page without unsaved changes simply shows the new version; one with changes stays dirty and autosaves on top of it. While a save is on its way the merge waits for the acknowledgment and then merges the store's current version, so a late or reordered notification never applies text older than the saved version. Merges run in stored form, so the page's line endings survive. Closing or quitting waits for current recovery; a storage failure keeps the window and Copy Markdown accessible.

The stored window navigates the whole notebook. Command-K (Ctrl-K elsewhere) opens a find palette built on Zed's picker. It lists pages whose title contains the query, the page that `find_page` resolves (an exact name, a unique title, or a daily date), and ranked full-text hits from the query index. Enter opens the choice; Shift-Enter opens it in the side pane. Results carry their request number and index generation, so a slower answer to an earlier query never replaces newer rows. Command-N (Ctrl-N) creates a page from a typed title with the reference naming rules. The page starts as `- ` and is refused when any page already uses that name, ignoring case.

Every navigation joins the history, the Recent list (12 kept, 6 shown), and the tab strip (30 kept). Command-[ and Command-] (Alt-Left and Alt-Right elsewhere) and the mouse back and forward buttons move through history without reordering Recent. Ctrl-Tab and Ctrl-Shift-Tab cycle tabs. Command-W (Ctrl-W) closes the active tab and falls back to the last remaining tab, then the Pages browser. Command-\ (Ctrl-\) mirrors the page into a second pane or closes it. The star in the tab strip toggles a favorite. Command-Shift-E (Ctrl-Shift-E) focuses the Files tree: arrows move, Right expands, Left collapses or moves to the parent folder, Enter opens, and Shift-Enter opens beside. Namespaces are logical: the Pages browser groups titles by the reference `namespaceOf` rule and never moves files. Tabs, favorites, recents, expanded folders, and the side pane are saved per notebook in `quire-workspace.json` beside the database. Destinations use page identities, so a rename keeps them.

Right-click, or Shift-F10 on the highlighted item, opens a pointer menu. A Files page offers Open, Open beside, Copy link (`[[Title]]`), Add to or Remove from favorites, New note here, Rename (F2), Move to… (Shift-F2), Reveal in Finder / Explorer in a folder notebook, and Delete page…; a Files folder offers New note here, Rename or move…, Reveal, and Delete folder…. Recent and Favorites entries offer Open, Open beside, Copy link, favorites, Rename or move…, Reveal, Delete page…, and on Recent, Remove from recent. A tab's menu closes it, the others, the tabs to its left or right, or all of them, then offers the page actions; Shift-F10 outside Files and the page opens the active tab's menu. The page's menu offers Cut, Copy, Paste, and Select all; on a selection Bold (Command-B, Ctrl-B outside Vim Normal), Italic, Strikethrough, Code, and Link to page, each adding or taking off the marks in one undo step; in a list item Bullet list or Numbered list (Write) with the current style ticked, Turn into task, Mark task done, or Reopen task, and Copy block reference or embed, which gives the item an ID when it has none. A right-click outside the selection moves the caret first. Arrows, Home, and End move through a menu, Enter or Space chooses, and Escape closes it and returns focus.

Delete page… in the page header, or Delete and Command-Backspace (Ctrl-Backspace) on a Files item, opens a dialog naming the page, or the folder with its page count and up to 20 paths, and how many links from other pages will point to a missing page. Enter confirms and Escape cancels. Deleting records tombstones for every page at once, so every computer on the notebook removes them while their history stays; a page saved elsewhere after the choice, or a page that appeared in the folder, refuses the whole deletion with the page named. Unsaved typing in an open page is saved into the tombstone, and the page then stays open read-only so nothing typed later revives it. Tabs, favorites, recents, history, the side pane, and the deleted folder's expanded state are cleaned up. Rename… in the page header, or F2 on a Files page, opens a dialog with the name selected. The file name and title change together, a front matter `title` follows, and every link to the page (wiki links and embeds, and relative Markdown links and images) is rewritten in one all-or-nothing write; open pages keep their unsaved typing. Taken names (ignoring case), names with a slash, invalid file names, and case-only changes show the reference message inline. In a folder notebook, Delete moves the note, or the folder with every file in it, to the system Trash, where you can restore it; the dialog says so and counts other files in the folder. Rename in a folder notebook moves the file through a journal, described below. Move… in the page header, or Shift-F2 on a Files item, asks for a path inside the notebook; F2 on a Files folder does the same for the folder. Enter first previews: the dialog names the move, how many other pages need link updates, those pages, and every link change as before and after, twenty at a time with Show more link changes. Nothing is written until a second Enter (Move), and editing the path drops the preview. A moved page keeps its title and block IDs, as in the reference app, which records the old title in front matter when the file name changes. Moving a folder moves every page inside it, keeping file names and titles, and rewrites links to each of them; other files stay where they are, so images the pages show are linked from the new place. A page changed after the preview refuses the whole move with nothing written, and the next Enter previews again. A folder cannot move inside itself.

History… in the page header lists the page's earlier saved versions with their times, newest first, including history imported from the reference app. Up and Down choose a version, and a read-only editor shows what restoring it changes in the current page as Zed diff hunks, unsaved typing included. Enter (Restore) makes the version the page's newest one in one checked save: an open page's unsaved typing is saved first and stays in history, and a page changed after the comparison refuses the restore and is compared again. Command-Enter (Ctrl-Enter) or Restore as a new page saves the version beside the page with fresh block IDs, as the reference app's only restore does, and opens it. Restoring is not an undo step; the replaced version stays in history.

Backups… in the page header (actions `quire_backup::ShowBackups`, `ChooseBackupFolder`, `BackUpNow`) shows the backup folder, Back up now, the last completed backup, and every completed backup with Verify and Restore…. The folder is remembered per notebook on this computer in `backup-folders.json` in application data and must lie outside the notebook's own data. While a notebook is open, Quire backs it up within a minute of opening when none is recent, then every hour, and waits 15 minutes after a failed automatic attempt, as `rt` does; every completed backup is kept. The hourly backup is skipped when nothing changed since the newest completed backup: each backup records a fingerprint of the notebook's files (path, size, modification time, and on macOS and Linux change time and inode, without reading contents, including the databases' write-ahead journals), and the next hourly check makes a new backup unless the fingerprint matches and every file of that backup is still present at its recorded size. An edit, a draft, an added attachment, or another application's change to the folder alters it; Git's data, the query index, and the window's tabs do not. Back up now always backs up. A backup is `<folder>/Quire Native/<notebook key>/<time>-<id>/`: a Quire notebook's `local.sqlite` and every cataloged attachment, or a folder notebook's files (without `.git`) under `notebook/` and Quire's state (recovery, history, journals, archive) under `state/`. Databases, including the reference app's `.quire` databases, are copied with SQLite's `VACUUM INTO` while the notebook stays open, never as raw live files. `manifest.json` records each file's SHA-256 and size and each database's row counts. The backup is written under a hidden `.partial-` name, verified from the drive, and only then renamed into place, so an interrupted or failed backup is never listed. A folder notebook changed during its backup fails with a message to retry rather than mixing versions. Verify reopens a backup read-only and checks every file, the database integrity and counts, every revision and draft, and the attachment catalog. Restore… asks for confirmation and a parent folder, verifies the backup, backs up the open notebook first, copies into a hidden folder, gives a Quire notebook a new identity (same revision IDs and history, everything queued to publish again), checks the copy, renames it to `Restored <time>`, and opens it in a new window; the old window closes once its pages are secured. Restored recovery drafts lose their base, so they open for review and never merge on their own. The open notebook is never written, and any failure removes only what the restore created. Backups are not readable by `rt`, and `rt` backups are not restored here yet. Tabs and the query index are rebuilt rather than backed up.

Sync… in the page header (actions `quire_sync::ShowSync`, `SyncWithGit`, `CheckSyncFolder`) shows where a folder notebook is synchronized and runs Personal Git, following `rt`'s `git-sync.ts`. It names the provider from the folder's real path (OneDrive, Dropbox, iCloud Drive, or Google Drive) and reminds you that a local save is not an upload. It lists notes the provider keeps only in the cloud (iCloud `.<name>.icloud` stubs, macOS `SF_DATALESS`, Windows Cloud Files attributes) and conflict copies whose names only a provider makes (Dropbox's "conflicted copy" names, copies of format 1 change files). Opening a notebook that is the root of a Git repository adds `/.quire/devices/` and `/.quire/ai/` to the repository's local exclude file and warns when they are already tracked. Enter a remote and Save remote; the first remote asks you to confirm the notebook is Personal, since Git sync never carries Work notes (this stands in for profiles until they exist). Remotes carrying credentials are refused; Git's own credential helper or SSH agent answers, and Git can never prompt. Sync with Git fetches, fast-forwards only when the remote alone moved and the folder is clean, refuses divergent histories and leaves both sides as they are, commits everything, and pushes without force. Notes still in the cloud stop the sync before the commit would record them as deleted. A failed push keeps the commit and shows its reason until a later sync succeeds; the remote, last successful push, and last error are remembered per notebook in `personal-git.json` in application data. Notes a sync brings in reload in open pages. `quire_store::git_sync::sync_quire` syncs a Quire notebook's change-file folder (commit, merge, push; a conflicting merge is aborted), but the window does not publish Quire notebooks to a folder yet. Everything was tested with local clones and a bare remote; real providers and network remotes are unverified. `cargo run --release -p quire_store --example git_growth -- 365` measures a synthetic year of repository growth.

Export as Markdown… in the page header (action `quire_exchange::ExportPageMarkdown`) saves the shown page as standalone Markdown, as `rt` does without AI: links read as their text, block references and embeds are written out (three levels deep), block IDs and created stamps are dropped, and images point at their files inside a folder notebook or at the stored attachment in a Quire notebook, or keep their notebook path. The save dialog suggests the page title as the file name and asks before replacing a file; Show file reveals it. Import a Markdown folder… (`ImportMarkdownFolder`) copies a folder's `.md` pages into the notebook, skipping dot entries and links, and leaves any page whose path the notebook already uses, ignoring case, unchanged; the report reads "Imported N pages and M other files." as in `rt`. The source is only read, and a folder inside the notebook is refused. Pages are read off the UI thread with a running count and Cancel, which writes nothing; then every page is created in one checked write, or none when a name is unusable on Windows or macOS or a page appeared meanwhile. Folder notebooks also get the other files at their relative paths, never replacing one, and import through the journal at most 1,000 notes per group, removing what a failing import created. Quire notebooks copy each other file an imported page links to into the attachment cache under its content name, in the same store request as the pages, and point those links (inline links and images, `![[...]]`, and `{{pdf: ...}}`, resolved from the page's folder, outside fenced code) at `attachments/<name>`; if the page write fails, the attachments it added are removed again. Files no imported page links to stay in the source, and the report says how many. Export notebook as Markdown… (`ExportNotebookMarkdown`) writes every page at its path, open pages with their unsaved typing as shown, plus a folder notebook's other files, into a chosen folder. A Quire notebook's linked attachments are copied to `attachments/<name>` at the folder's root and each link is rewritten from its page's folder (`../attachments/<name>` one level down), so the folder reads as a folder notebook and imports back unchanged; it asks before replacing existing files, stages everything in a hidden folder so Cancel or a failure leaves nothing, and reports what Markdown cannot carry (history, other competing versions, recovery drafts, linked attachments not on this computer, sync logs and settings). The planning lives in `quire_core::exchange` and is checked against frozen `rt` code; regenerate its vectors with `bun tools/exchange-vectors.ts`.

Import Roam data… (`quire_exchange::ImportRoamData`) asks for a Roam JSON or EDN export (EDN when the file ends in `.edn`) and a parent folder, then creates the folder notebook `Roam import <time>-<id>` there, as `rt` does. Each Roam page becomes a note named after its title (made portable, with a numbered suffix for names that collide ignoring case) holding the original title in front matter and the blocks as a Markdown outline whose `^uid` markers keep Roam's UIDs; UIDs Markdown cannot hold get fresh `b-` IDs, and the references to them follow. Headings and `{{TODO}}`/`{{DONE}}` markers become Markdown, other macros stay as text, and nothing is downloaded or executed. `.quire/roam.json` keeps every page and block attribute, `.quire/source.json` or `source.edn` the export's exact bytes, and `.quire/import-report.txt` the report. EDN is read as data only: DataScript datoms are rebuilt into pages with children ordered by `:block/order` (unordered ones after, by entity ID), users resolved, and blocks no page reaches recovered on a "Roam recovered blocks" page. Exports over 100 MB, text that is not UTF-8, duplicate UIDs or titles, and malformed or cyclic outlines are refused with `rt`'s messages. Reading, reference parsing (with the editor's Markdown grammar, a batch at a time), conversion, and writing run off the UI thread with progress and Cancel; the notebook is written into a hidden staging folder that one rename publishes, so Cancel or a failure leaves the parent folder as it was. The new notebook opens in its own window on its Pages list, with the report in its notices. Export Roam JSON… (`ExportRoamJson`) writes every page of either notebook kind, open pages with their unsaved typing, to a new JSON file (suggested as `Quire-<time>.json`) and its report beside it as `<file>.report.txt`. Pages and blocks unchanged since a Roam import come back with their original attributes; edited blocks keep theirs except the edit stamps, other Markdown blocks become Roam blocks (headings, tasks, links, embeds, and `[[Page#^id]]` references converted), and custom front matter becomes a YAML code block. The export refuses an existing file, a destination inside the notebook or Quire's data folders, pages with unsaved recovery drafts, and an unreadable `.quire/roam.json`; extra report lines join the notebook's notices. The rules live in `quire_core::exchange::roam` and `edn` and match frozen `rt` code byte for byte; regenerate the vectors with `bun tools/roam-vectors.ts`. A 2,000-page, 50,000-block graph (5.3 MB) imports in 73 ms and exports in 100 ms in a release build on this Mac.

Command-J (Ctrl-J) opens today's daily page, creating it from the daily layout when missing. The layout comes from the replicated `s-notebook` settings page, as in the reference sync engine, and reaches the query index before its first query. The Daily notes browser lists dated pages newest first, marks duplicates of a date with "also", and edits the layout. Saving writes the settings page and restarts the index; existing pages are never moved. Unreadable or newer settings stay read-only and unchanged.

The Tags browser (the Tags button) lists every tag with its block count, labelled by its first use. Type to filter; the sort button cycles name, most blocks, and fewest blocks. Arrows move, Enter opens the tag page, and Command-Enter (Ctrl-Enter) or the checkbox adds the tag to the selection. With tags selected, type a new name and press Enter or Rename… to preview a rename, which also moves nested tags and merges into an existing tag, or press Delete… to preview removing exactly those tags. The preview lists every change by page, twenty at a time, and Apply writes all pages or none through the atomic multi-page save. Invalid names, an empty selection, more than 1,000 pages, and a page changed after the preview show inline. A tag page lists each block using the tag, grouped by page, with up to four parent blocks above it and eight nested blocks below. Its filter matches block text or page title; Enter opens the source page and Shift-Enter opens it beside.

The Tasks browser (the Tasks button) lists Due, Upcoming (the next 7 days), Inbox, Next, Waiting, Someday, Projects, and Done with their counts; `[` and `]` switch lists and the choice is remembered in the workspace. Due lists open tasks due today or earlier, earliest first; Done lists the latest completions first; undated tasks come last. The filter matches task text and page titles, and `-word` or `-#tag` hides tasks. A project menu narrows a list to one project's actions. Arrows move, Enter opens the source page, Shift-Enter opens it beside, Command-Enter (Ctrl-Enter) ticks the highlighted task or reopens a done one, and Command-Shift-Enter cycles its state. Space adds a task to the selection, Shift-Space selects a range, and Escape clears it; 1 to 5 move the selection, or the highlighted task, to Inbox, Next, Waiting, Someday, or Done, also from the toolbar. D, C, and Shift-D open the due, created, or completed date: type YYYY-MM-DD, `today`, `tomorrow`, `+3`, or a weekday and press Enter; an empty date clears the stamp. Every change reads the touched pages fresh and writes all of them or none, so a task changed since it was listed is refused with the pages named, and an open page keeps its unsaved typing. Projects lists project pages (a `#project` block, a `Projects/` title, or a `project` or `project/<name>` front matter tag) as Active (an open action), Inactive, or All with counts, remembered in the workspace, each with its open and done counts and its next actions or a "No next action" warning; R or "Review actions" lists its next actions, else the list of its first open action. "New project" creates `Projects/<name>` with a first next action. Command-Shift-T (Ctrl-Shift-T) opens Tasks with the capture field focused: Enter appends `- [ ] text #inbox ➕ [[today]]` to the Inbox page, creating it when missing, with the chosen project linked, then shows the list the task went to.

Under the main page, Linked references lists each referring block once, grouped by page with its parents and nested blocks. Daily pages come newest first; the order button switches to oldest first and is remembered per page in the workspace. With more than one reference a filter line accepts `#tag`, `[[Page]]`, `project:Name`, words, and quoted words, each negatable with `-`, shows an "N of M" count and any parse error, and offers chips for the most frequent tags, pages, and projects: click adds the term, Alt-click excludes it, and clicking again removes it. Escape clears the filter, and each page keeps its own filter for the session. Command-Shift-R (Ctrl-Shift-R) focuses the panel. The references, the filter result, and the chips come from one index step, and these views re-run their queries whenever the index reports a change, dropping replies to superseded requests and older index generations.

Opening a database performs native schema validation and upgrades. It never opens or converts a Markdown folder; folder notebooks open separately, as described next. It reports checkout body counts and time to buffer readiness; upgrades can read additional bodies to build indexes. These figures do not establish first-editable or release performance acceptance. Native desktop close/quit acceptance remains open; the guards have headless GPUI coverage.

Open a folder of ordinary Markdown files in place with `cargo run -p quire --locked -- --notebook-folder /path/to/notes [--page Folder/Note.md]`; without `--page` the first note in path order opens. Each `.md` file is a page whose identity derives from its path; dot entries, `node_modules`, `dist`, `out`, and symbolic links are skipped, and two paths that differ only in letter case open as the first, with a warning. Opening writes nothing inside the folder: recovery drafts, saved history, the query index, and tabs live under the application data folder in `folder-notebooks/<hash of the folder path>`. Saves follow the reference folder notebook. Each records the text as a recovery draft first, then writes a synced temporary file beside the note, checks that the file on disk is still the version the page was opened or last saved from, keeps the replaced text in history, and renames the temporary file into place, so other programs see the old note or the new one, never part of either. A new note is created only if no file appeared at its name. A note changed on disk since it was read, a read-only note, or a note that resolves outside the folder through a link is never written; the save is refused and the text stays in recovery. Zed's file watcher rereads changed notes. A page without unsaved edits shows the new version. A page with unsaved edits, or whose save was refused, stops saving and shows "This file changed outside Quire" or "This file was removed outside Quire" with Save my version as a copy (a new page with fresh block IDs), Use disk version (after confirmation, discarding the draft), and Compare versions (the disk text). A draft left by a crash reopens and saves at once when the file is unchanged, or opens in that conflict when the file changed. The query index reads the folder's files itself, rereads only files whose size or times changed, and answers the same queries as for a Quire notebook. The daily layout comes from the reference app's `.quire/notebook.json`; saving a layout rewrites that file in the reference format in one rename, and only when it still holds the version Quire read, so a layout the reference app saved meanwhile is never overwritten. A newer or invalid settings file stays read-only. Changes across several notes (a rename with its links, bulk tag and task edits) check every note, record a synced journal in the state folder, then write each note; a renamed page's new file is created without replacing anything (a name taken in any letter case is refused) and its old file is archived in the state folder with its history carried over. An interrupted change finishes the next time the folder opens, with a notice; a note changed meanwhile stops it, and the journal and every version stay for review. The notice area then lists each stuck change with where its notes stand (changed since the change was planned, still to update, already updated) and offers Retry, which finishes it once the changed note is put back and never overwrites it, and Set aside, which leaves every note as it is and moves the journal to `transactions/set-aside` in the state folder, keeping each planned version. Because a page's identity follows its path, tabs, favorites, recents, and history follow a renamed page. Unsaved drafts the reference app left in `.quire/devices/<device>` (its `durability.sqlite` and older `recovery/*.json`) and its history, including `.quire/history` snapshots, are copied into the state folder and read there, so the notebook is never written. Each draft becomes a recovery draft under the rules above; one for a page that already has unsaved work in Quire becomes a separate note under `Recovered drafts/`. A notice lists the recovered pages with buttons to open each. Quire writes nothing else into `.quire`, and the reference app's records stay unchanged. Page history, described above, lists the notes' saved versions, the imported ones included.

Each pane has local Find and Replace. Use Cmd-F / Cmd-Option-F on macOS, or Ctrl-F / Ctrl-H elsewhere. Enter and Shift-Enter navigate matches; Escape returns to the editor. In the replacement field, Enter replaces one match and Cmd-Enter / Ctrl-Enter replaces all. Replacements share the document's undo history. Vim supports `/`, `?`, `n`/`N`, word-under-cursor search, counts, cancellation, and search motions with operators.

Use `:` for editor-local commands, including line jumps, visual/count ranges, substitution, settings, delete, and sort. For example, `:%s/old/new/g` replaces throughout the note. Errors stay in the prompt for correction; Escape cancels. Up/Down recall command history by prefix and restore unfinished input. History stays in memory for the application session. Named registers work across panes and survive toggling Vim.

Editable stored pages support `:w`, `:write`, and `:wq`. Write-quit closes the window only after the latest text is saved locally and retained pages are secured. Save errors appear in the page status and keep the window accessible. Force forms save like any other write: a page changed elsewhere is merged, never overwritten. Filename and range writes remain unavailable; use Copy Markdown for the complete source. In-memory examples and read-only pages reject writes. AI commands still need their notebook-service integration.

Settings (Cmd-, on macOS, Ctrl-, elsewhere, or the sidebar's Settings button) holds the reference app's preferences: appearance (System, Light, or Dark), Vim bindings, Format tags, where quick capture goes (Inbox page or today's daily page), font family, font size (10 to 40 px), and line spacing (1.2 to 2.5). Defaults match the reference app: Vim on, Pragmata Pro Mono Liga at 16 px with 1.85 line spacing and a Lilex fallback, tags formatted, and capture to Inbox. They are Zed settings in Quire's `settings.json` (in the `QuireNative` configuration folder), so a hand edit applies as soon as the file is saved, and Restore defaults removes only these keys. Format tags and the capture target live in its `quire` section. On first launch, when no settings file exists, Quire imports the reference app's `appearance.json` and its `quire.editor.settings` value, read-only from that app's Chromium local storage (falling back to the older Threadnote folder and key names). Daily-note layout stays in the notebook, where the reference app also reads it.

With Format tags on, Write shows tags as labels in the reference app's 24 tag tones (for example `#idea`, `#question`, `#doc`, and `#learning`); nested tags such as `#book/fiction` take their family's tone, other tags a neutral one, and Source always shows raw text. The sidebar's Light / Dark button switches between light and dark as an explicit choice.

F1 opens Help & shortcuts, available offline: the reference guide's topics, searchable, followed by a keyboard shortcut reference generated from the keymap actually bound, so it lists every binding with its action's own description and never drifts from the keys. README.md (sidebar or Help) opens the reference app's rendering sample in a window of its own. The sample belongs to no notebook, so its tasks and tags never reach a notebook's queries, index, backups, or exports; edits last until Quire quits, and Reset sample restores it as one undo step.

Use Rust 1.98.1, Bun, and Node 26 for development. macOS builds require Xcode with the Metal tools. GPUI and its platform/support crates are copied under `vendor/zed`; building does not require either sibling checkout.

```sh
bun install --frozen-lockfile
bun run verify:vendor
bun run test:reference
cargo test -p quire --locked --features test-support
bun run test:vim-search
bun run test:vim-command
bun run test:vim-mark
cargo test -p quire_store --locked
bun run test:storage-crash
cargo build -p quire --locked
bun run dev
```

`bun run dev` requires a regular desktop terminal. The macOS Codex sandbox denies desktop services, including the pasteboard; the launcher detects that environment and explains how to proceed. Headless GPUI tests still run there. In this sandbox, build commands use `CARGO_HOME=/private/tmp/quire-cargo` because the shared Cargo cache is read-only.

The native development app uses `QuireNative` data/config paths, separate from Zed and the Electron app. The earlier input harness is available through `cargo run -p quire -- --input-harness`. The current debug executable produces a macOS linker warning about large unwind metadata; release performance and native desktop acceptance remain unverified.

Run `cargo run -p quire --locked -- --excerpt-harness` in a regular desktop terminal to inspect semantic excerpts. The right pane follows block `b-welcome` and its descendants from the left pane's document. Adding, deleting, or reparenting children updates the same view, with shared undo/redo. Missing or duplicated IDs disable editing and show how to restore the block in Source. It starts in Source; its mode control can enable the current Write projection. Complete Write rendering and notebook embed workflows remain unfinished.

`cargo run -p quire --locked -- --write-harness` opens the example note with list markers and block IDs hidden in the right pane. Both panes edit the same source. Write edits a page as an outline; Source keeps Zed's ordinary Markdown editing. Without Vim, or in Insert mode: Enter continues a list item, splits its text with the block ID kept on the first part, nests a new first child under a parent with visible children, and outdents or ends an empty item. Fenced code blocks are highlighted in Write and Source with the theme's syntax colors. Tasks follow `quire_core::tasks`, ported from rt. A list item whose text starts with `[ ]`, `[x]`, or a Roam `{{TODO}}`/`{{[[DONE]]}}` marker is a task; `#next`, `#waiting` (or `#pending`), `#someday`, and `#done`, also as `#[[waiting]]`, set its state, and Inbox is the default. `➕ [[date]]` records when it was made, `📅 [[date]]` when it is due, and `✅ date` when it was done. Without a due stamp, a task is due on the earliest date it or an ancestor links (never the created link) or on the daily page it sits on, and it also carries its ancestors' page links. In Write, Source, and embedded excerpts, Cmd-Enter (Ctrl-Enter elsewhere) completes the task at the caret, reopens a done one, or makes the list item, paragraph, or empty line a task stamped with today; Cmd-Shift-Enter cycles Inbox, Next, Waiting, Someday and reopens a done task into Inbox. Wiki links (`[[Page]]`, `[[Page|label]]`, `![[Page]]`, `[[Page#^id]]`) and Roam references (`((id))`, `((id|label))`, `{{embed: ...}}`) resolve through the query index, unsaved text included. Images and PDFs show inline in Write, below their line, the way full embeds do: Markdown images (`![alt](src)`), media wiki embeds (`![[file.png]]`, `![[paper.pdf#page=3]]`), and Roam PDF embeds (`{{pdf: ...}}`, `{{[[pdf]]: ...}}`). In a Quire notebook `attachments/<name>` resolves to the store's content-named attachment cache from any page folder; a folder notebook reads files beside its notes. PDFs stored in the notebook render with PDFium; remote and `data:` PDFs render with hayro, a memory-safe Rust renderer, so untrusted bytes never reach C++. Each PDF opens on its own thread in a 520-pixel scrolling view with a toolbar: the page number, zoom out and in (50% to 400%, also Cmd-minus and Cmd-equals while the PDF has focus), Find in PDF with Enter and Shift-Enter for the next and previous match, and Open in system viewer. `#page=N` opens at that page. Attach file (Cmd-Alt-A, Ctrl-Alt-A elsewhere) chooses files and links them at the caret; pasting an image and dropping files on a page do the same. Each file streams into the store's attachment cache under its SHA-256 name, as `rt` stores replica attachments, and the links use `rt`'s forms in one undoable edit: `![[...]]` for PDFs, `![](<...>)` for images, and `[name](<...>)` for other files. Saving a page still requires every attachment it references, so publication carries them. In a folder notebook the file is copied into the notebook's `attachments` folder as `<8 hex>-<name>` (`<>:"/\|?*` become `-`), as `rt`'s vault does, never replacing a file and refusing a linked `attachments` folder; the link is written from the page's folder (`../attachments/...` in a subfolder), where `rt` writes `attachments/...` from any page.

The storage library reuses Zed's `sqlez` with a fallible file-open path, WAL/FULL, FTS5, and macOS fullfsync. SQLite is pinned to bundled 3.54.1. Notebook identity/schema checks protect existing databases. Saves commit revisions, heads, outbox entries, and matching recovery changes together. A bounded worker keeps SQLite and publication I/O off its caller's thread. `NotebookStore::publish_to` publishes one frozen batch to an existing format 1 notebook folder. It delivers verified attachments first, preserves immutable files, and adopts a matching pending batch after interruption. Conflicting writer sequences, unexpected own batches, changed notebook identities, and incomplete files leave local revisions pending. Publication acknowledges the local folder; peer delivery and power-loss durability need separate acceptance checks.

`NotebookStore::import_batch` applies an incoming graph and cursor atomically. It leaves competing heads in place; the rescan that called it merges them afterwards. Missing parents and sequence gaps wait; malformed graphs and forks preserve local data. Imported wire records retain unknown fields and lone surrogates. Own frozen publications remain with the publisher for durable acknowledgment. Both operations run through the bounded worker.

`NotebookStore::rescan` discovers delivered device chains, retries parent dependencies, and streams requested attachments into the verified local cache. Count and payload budgets return continuations across devices and attachment names; one oversized item can proceed alone in each phase. Partial delivery and writer forks leave source files unchanged. Rescans can adopt an observed frozen publication while retaining later local saves. After a complete graph pass that reconciles this device's own log, a rescan merges every page that still has competing heads in one transaction and reports the merges in `RescanReport::merged`. Batches commit independently, so a later storage error can leave an imported prefix; callers must refresh mounted pages after errors as well as successful reports. Directory discovery currently enumerates filename metadata. The full mixed-runtime convergence schedules, checkpoints/status, watcher lifecycle, Windows synchronization, and editor integration remain unfinished.

Competing heads merge deterministically, matching `rt` 0.9.57 and its Go terminal app byte for byte. `quire_core::merge::merge_text` ports `src/core/merge.ts`: a three-way line merge against the newest common ancestor, word by word where both sides changed one line, keeping both versions (older head first, without a repeated block ID) only where the same words changed. It works on UTF-16 code units, so lone surrogates merge unchanged. A save that leaves several heads merges inside its own transaction and returns the merge with its overlap count. Merge revisions carry this device and the save time or the store clock (`open_with_clock` injects one), but their IDs depend only on content, so two computers merging the same heads produce the same ID. An edit outlives a deletion, and of two moves the newer wins. Rescans merge after the whole graph pass rather than inside each batch, as `rt` does, and only once the rescan has reconciled this device's own log: a merge in the outbox would make the importer refuse this device's own later batches during a rebuild. For the same reason opening a store does not merge, unlike `rt`; the first reconciled rescan merges heads kept by older builds or left by a crash between an import and its merge. Each page merges under its own savepoint, so a page whose merge fails keeps its heads and appears in the rescan problems. Merges never require their attachments locally, but publication still does, so a merge that references an undelivered attachment waits to publish until it arrives. Generate the differential vectors with `bun tools/merge-vectors.ts`.

Schema 2 retains attachment requests and known batch hashes across restart. Requests clear with a verified attachment's catalog commit; historical hashes detect older writer forks. Schema 1 upgrades atomically while preserving drafts, local revisions, pending publication, and the attachment catalog. The one-time upgrade reads legacy bodies individually through pages of 128 IDs to reconstruct dependencies. Migrated hash history starts at recorded cursors; unavailable earlier hashes remain unknown. Routine metadata queries use bounded pages without reading page bodies.

Schema 3 prevents coalescing a local pending revision after it appears in an imported peer batch. Since `rt` 0.9.57, an import removes every unselected outbox entry that the batch already publishes, from any device, because two computers can create the identical revision and others may build on it. A frozen selection keeps its exact bytes and records the observation with the imported cursor. Neither path changes local revision provenance. Upgrades from schemas 1 and 2 conservatively protect all existing pending revisions because those databases did not record peer observation. This prevents future deletion; it cannot reconstruct a revision already removed by an older build.

Schema 4 adds checksummed, versioned title metadata. Save/import transactions update it with the revision, and coalescing removes obsolete rows through foreign keys. A schema-3 upgrade reads current heads one body at a time through pages of 128 IDs; unrelated history stays on demand. The additive schema and backfill commit together. Older attachment upgrades retain their separate historical-body pass.

`page_metadata` returns selected heads in canonical page-identity order, including conflicts and tombstones. It limits both rows and encoded payload bytes, allowing one oversized row to progress alone. SQLite checks byte lengths before loading title payloads, and routine reads never load revision bodies. Titles follow the editor's normalized line breaks while keeping stored text and raw UTF-16 strings unchanged. Generate the 1,080 raw/editor title vectors with `bun tools/lossless-title-vectors.ts`. Missing, damaged, or outdated derived rows report a rebuild error; `rebuild_metadata` runs through the worker and rolls back if a required head is unreadable. The query index is a separate, disposable `query-index.sqlite` beside the notebook database. Its own worker thread opens it with the notebook attached read-only, so index work never waits behind saves and never writes notes. A catalogue of selected live heads comes from checksummed title metadata without reading bodies. The app then analyzes each unanalyzed head on the background executor with the editor's own block, reference, and tag code, through a detached Zed snapshot, and stores rows keyed by immutable revision ID. Queries mirror the reference store: `find_page` (exact name, then a unique title, then a date), `backlinks` (by name or title, owned date links, and resolving block references), `mentions`, `resolve_block`, `tagged_blocks`, and `tag_names`, ordered with ICU root collation as `localeCompare` orders them. A damaged file, another notebook's index, or a new format or analyzer version is deleted and rebuilt. The window shows pages left to index and any index error; editing never depends on it. Generate the 1,254 analysis vectors with `bun tools/page-index-vectors.ts`; native blocks, links, and tags must match the reference on every one, from fresh and incrementally edited buffers. `search` mirrors the reference `SearchIndex`: an FTS5 `unicode61` table with a title row per page and a row per block, terms from `[\p{L}\p{N}_-]+` joined as required prefixes, bm25 order, 24-token snippets, and 40 results. Search rows leave with their page through a foreign-key cascade and delete trigger. Generate its 33-query oracle with `bun tools/search-vectors.ts`. One deliberate difference: the reference indexes raw disk text, so CRLF pages keep carriage returns inside snippets; the native index uses the editor's normalized text. Open pages shadow their committed rows: after typing pauses for 150 ms, the page's live text is analyzed in the background and stored in TEMP tables on the index connection, and lookups read views that drop the page's committed rows while it is open, so a page never counts twice. A closed page keeps its overlay until the index has analyzed its last committed head, so it never disappears between a save and its analysis. Search stays committed-only, as in the reference, whose index reads saved files. `with_generation` returns a query together with a generation that moves whenever committed rows, analysis, or overlays change, so callers can drop stale results.

Linked references come from `linked_references`: each referring block once, daily pages newest (or oldest) first and other pages by path, with the context that filters read (the block, its parents and children, and its page's title, links, and tags, front matter tags included). `quire_core::reference_filter` parses `#tag`, `[[Page]]`, `project:Name`, words, and quoted words, each negatable with `-`; `filter_names` resolves page and project terms and `reference_facets` ranks one-click suggestions. All 17 cases of the shared `tests/fixtures/reference-filters.json`, copied unchanged from rt and also run by its terminal app, pass through the production analyzer and index. The window's Linked references panel drives them.

Bulk tag edits plan in `quire_core::tag_edits`: rename moves each chosen tag and the tags nested under it, delete removes only the chosen tags, and both rewrite front matter `tags` in the form the page uses. The index narrows the work to pages whose tag keys the edit touches, and the editor analyzer supplies the tag tokens, so tags in code and links stay. Applying writes every changed page or none: open pages save their typing first and hold further saves, a page changed since the preview refuses the whole edit, and open pages then take in their new version. The Tags browser drives it, and task changes from the Tasks browser use the same path (`page_writes`). Renames and deletions use it too: a deletion goes through the store's `delete_if_heads`, which also refuses when a page appeared in the chosen folder. `quire_core::relocate` ports the reference `planRelocation`; `bun tools/relocate-vectors.ts` regenerates its 175 vectors from the frozen copy in `tests/reference/core/relocate.ts`, plus 68 folder-move vectors that apply the frozen `planRelocation` to each page of the folder in turn (without the title a page move records, since folder moves keep file names) and must equal `relocate_pages` doing every move at once, and the native link and URL ranges the app feeds it must match the reference parse on every vector page.

Task rows (index format 4, analyzer version 5) keep each task's state, text, tags, links, and completion date, plus the sources of its created and due dates: stamp targets, its own dated links, and its ancestors' links.
