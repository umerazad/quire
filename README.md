# Quire native

The Rust/GPUI rewrite is underway. The default executable hosts Zed's editor and Vim in two panes sharing an in-memory example note. Each pane can switch between Source and Write presentation using the copied Markdown and inline grammars. Existing stored pages support editing, recovery, and local saves. Daily-page navigation and the remaining application workflows are still in [the task queue](plans/native-rewrite-tasks.md).

Open a stored page with its native database and original identities:

```sh
cargo run -p quire --locked -- \
  --notebook-db /path/to/local.sqlite \
  --notebook-id notebook-id --writer-id writer-id --page-id page-id
```

The window loads one selected revision and optional recovery through the storage worker. Concurrent opens within a notebook session share one buffer and analysis model. Recovery takes precedence when opening a page. Conflicts, deleted versions, and missing pages remain read-only until their resolution or creation workflow is available. A recovery draft whose base version is in storage and whose page still lives at the draft's path opens editable and is saved from that base as soon as editing starts, so the store merges it with anything saved since. Other drafts, including those typed into a version this store does not have or moved to another path, open read-only and stay for review. Unrepresentable UTF-16 strings produce an actionable error without creating a lossy buffer. A failed page read can be retried after its cause is corrected; startup failures require reopening the notebook.

Copy Markdown copies the whole page, including recovered text, with its original line endings. It captures the page when clicked and prepares the clipboard contents in the background. The shared source mapping preserves untouched LF, CRLF, and bare-CR endings through native edits and undo; new line breaks use the first opened line-break style, or LF for a page without line breaks.

Typing records recovery after 100 ms of inactivity and saves locally after 450 ms, and no later than 2 s after the first unsaved edit during steady typing. Save locally, Cmd-S on macOS, or Ctrl-S elsewhere saves immediately. Status distinguishes recovery from a committed local save; folder publication remains separate. A save acknowledges its captured version, so later typing stays dirty. If the page changed elsewhere, the save still goes out from the version the editor opened, the store merges both inside the save transaction, and the editor shows the merged text while keeping anything typed during the save. Where both sides changed the same words, both versions are kept and the status names the page. Saving to a page deleted elsewhere restores it; an unchanged page saved from a deleted version stays deleted, and the status says to edit and save to restore it. `PagePersistence::absorb` brings another writer's version into an open page: the edits made since the last saved text merge into it as one buffer edit that keeps cursors and anchors and stays out of undo history. A page without unsaved changes simply shows the new version; one with changes stays dirty and autosaves on top of it. While a save is on its way the merge waits for the acknowledgment and then merges the store's current version, so a late or reordered notification never applies text older than the saved version. Merges run in stored form, so the page's line endings survive. Closing or quitting waits for current recovery; a storage failure keeps the window and Copy Markdown accessible.

The stored window navigates the whole notebook. Command-K (Ctrl-K elsewhere) opens a find palette built on Zed's picker. It lists pages whose title contains the query, the page that `find_page` resolves (an exact name, a unique title, or a daily date), and ranked full-text hits from the query index. Enter opens the choice; Shift-Enter opens it in the side pane. Results carry their request number and index generation, so a slower answer to an earlier query never replaces newer rows. Command-N (Ctrl-N) creates a page from a typed title with the reference naming rules. The page starts as `- ` and is refused when any page already uses that name, ignoring case.

Every navigation joins the history, the Recent list (12 kept, 6 shown), and the tab strip (30 kept). Command-[ and Command-] (Alt-Left and Alt-Right elsewhere) and the mouse back and forward buttons move through history without reordering Recent. Ctrl-Tab and Ctrl-Shift-Tab cycle tabs. Command-W (Ctrl-W) closes the active tab and falls back to the last remaining tab, then the Pages browser. Command-\ (Ctrl-\) mirrors the page into a second pane or closes it. The star in the tab strip toggles a favorite. Command-Shift-E (Ctrl-Shift-E) focuses the Files tree: arrows move, Right expands, Left collapses or moves to the parent folder, Enter opens, and Shift-Enter opens beside. Namespaces are logical: the Pages browser groups titles by the reference `namespaceOf` rule and never moves files. Tabs, favorites, recents, expanded folders, and the side pane are saved per notebook in `quire-workspace.json` beside the database. Destinations use page identities, so a rename keeps them.

Command-J (Ctrl-J) opens today's daily page, creating it from the daily layout when missing. The layout comes from the replicated `s-notebook` settings page, as in the reference sync engine, and reaches the query index before its first query. The Daily notes browser lists dated pages newest first, marks duplicates of a date with "also", and edits the layout. Saving writes the settings page and restarts the index; existing pages are never moved. Unreadable or newer settings stay read-only and unchanged.

The Tags browser (the Tags button) lists every tag with its block count, labelled by its first use. Type to filter; the sort button cycles name, most blocks, and fewest blocks. Arrows move, Enter opens the tag page, and Command-Enter (Ctrl-Enter) or the checkbox adds the tag to the selection. With tags selected, type a new name and press Enter or Rename… to preview a rename, which also moves nested tags and merges into an existing tag, or press Delete… to preview removing exactly those tags. The preview lists every change by page, twenty at a time, and Apply writes all pages or none through the atomic multi-page save. Invalid names, an empty selection, more than 1,000 pages, and a page changed after the preview show inline. A tag page lists each block using the tag, grouped by page, with up to four parent blocks above it and eight nested blocks below. Its filter matches block text or page title; Enter opens the source page and Shift-Enter opens it beside.

Under the main page, Linked references lists each referring block once, grouped by page with its parents and nested blocks. Daily pages come newest first; the order button switches to oldest first and is remembered per page in the workspace. With more than one reference a filter line accepts `#tag`, `[[Page]]`, `project:Name`, words, and quoted words, each negatable with `-`, shows an "N of M" count and any parse error, and offers chips for the most frequent tags, pages, and projects: click adds the term, Alt-click excludes it, and clicking again removes it. Escape clears the filter, and each page keeps its own filter for the session. Command-Shift-R (Ctrl-Shift-R) focuses the panel. The references, the filter result, and the chips come from one index step, and these views re-run their queries whenever the index reports a change, dropping replies to superseded requests and older index generations.

Opening a database performs native schema validation and upgrades. This path does not open or convert a legacy Markdown folder. It reports checkout body counts and time to buffer readiness; upgrades can read additional bodies to build indexes. These figures do not establish first-editable or release performance acceptance. Native desktop close/quit acceptance remains open; the guards have headless GPUI coverage.

Each pane has local Find and Replace. Use Cmd-F / Cmd-Option-F on macOS, or Ctrl-F / Ctrl-H elsewhere. Enter and Shift-Enter navigate matches; Escape returns to the editor. In the replacement field, Enter replaces one match and Cmd-Enter / Ctrl-Enter replaces all. Replacements share the document's undo history. Vim supports `/`, `?`, `n`/`N`, word-under-cursor search, counts, cancellation, and search motions with operators.

Use `:` for editor-local commands, including line jumps, visual/count ranges, substitution, settings, delete, and sort. For example, `:%s/old/new/g` replaces throughout the note. Errors stay in the prompt for correction; Escape cancels. Up/Down recall command history by prefix and restore unfinished input. History stays in memory for the application session. Named registers work across panes and survive toggling Vim.

Editable stored pages support `:w`, `:write`, and `:wq`. Write-quit closes the window only after the latest text is saved locally and retained pages are secured. Save errors appear in the page status and keep the window accessible. Force forms save like any other write: a page changed elsewhere is merged, never overwritten. Filename and range writes remain unavailable; use Copy Markdown for the complete source. In-memory examples and read-only pages reject writes. AI commands still need their notebook-service integration.

Use Rust 1.98.1, Bun, and Node 26 for development. macOS builds require Xcode with the Metal tools. GPUI and its platform/support crates are copied under `vendor/zed`; building does not require either sibling checkout.

```sh
bun install --frozen-lockfile
bun run verify:vendor
bun run test:reference
cargo test -p quire --locked --features test-support
bun run test:vim-search
bun run test:vim-command
bun run test:vim-mark
cargo test -p quire_store --locked
bun run test:storage-crash
cargo build -p quire --locked
bun run dev
```

The right pane follows block `b-welcome` and its descendants from the left pane's document. Adding, deleting, or reparenting children updates the same view, with shared undo/redo. Missing or duplicated IDs disable editing and show how to restore the block in Source. It starts in Source; its mode control can enable the current Write projection. Complete Write rendering and notebook embed workflows remain unfinished.

`cargo run -p quire --locked -- --write-harness` opens the example note with list markers and block IDs hidden in the right pane. Both panes edit the same source. Projection spans come from the current Markdown parse and update after edits, including newly inserted blocks. Partial delete/paste, clearing and retyping, delete/undo, stale parses, and subtree mapping have regression tests. Vim line changes preserve block and task prefixes plus IDs, while line deletion removes the whole source line even at EOF; undo works from the Source pane. Empty list/task items at EOF have differential parser coverage. The remaining structural editing cases are still pending.

Each pane's Source/Write button switches its presentation. Cmd-Shift-M on macOS, or Ctrl-Shift-M elsewhere, switches the focused editor. Source exposes the original syntax for direct editing. Switching keeps the same buffer and shared undo history, retains user folds, and rebuilds Write spans from the current parse.

Write edits a page as an outline; Source keeps Zed's ordinary Markdown editing. Without Vim, or in Insert mode: Enter continues a list item, splits its text with the block ID kept on the first part, nests a new first child under a parent with visible children, and outdents or ends an empty item. A continued task starts unchecked in the same marker style, and a numbered item gets the next number. Tab and Shift-Tab move an item with its children one level; a bare `-` becomes a bullet first. Backspace at a text start removes a checkbox, then joins the item to the block above; Delete at a text end pulls the next block in. An empty bullet with blocks after it is removed and its children lift a level; a lone empty bullet stays. Merging refuses blocks with IDs and never edits collapsed children. Pasting several lines into a list item makes each line a block, keeping relative nesting. Alt-Up/Down, Alt-Shift-Up/Down, and Cmd-Shift-Up/Down (Ctrl-Shift elsewhere) swap an item and its children with a sibling. Cmd-Alt-[ and Cmd-Alt-] (Ctrl-Shift-[ and ] elsewhere) collapse and expand a block's children. Cmd-Shift-7 (Ctrl-Shift-7) numbers the list at the cursor or turns it back into bullets; the `quire_outline::NumberList` and `BulletList` actions convert to one style. In Vim normal mode, `o` and `O` open sibling blocks, `J` joins blocks, `>>` and `<<` move a subtree, and `za`, `zc`, and `zo` fold children. Each command is one undo step; edits renumber the numbered runs they touch. On a task line, Home, `0`, and `^` reach the text, then the checkbox, and Left from the checkbox reaches the line above. Code, tables, raw HTML, and headings keep ordinary editing. Embedded excerpts and zoom are not outline views yet.

Write renders square task markers and Roam TODO/DONE markers as native checkboxes. Click or focus a checkbox and press Enter/Space to complete or reopen the task; Escape returns to the editor. A callback from an obsolete widget cannot toggle text that has become code.

Tasks follow `quire_core::tasks`, ported from rt. A list item whose text starts with `[ ]`, `[x]`, or a Roam `{{TODO}}`/`{{[[DONE]]}}` marker is a task; `#next`, `#waiting` (or `#pending`), `#someday`, and `#done`, also as `#[[waiting]]`, set its state, and Inbox is the default. `➕ [[date]]` records when it was made, `📅 [[date]]` when it is due, and `✅ date` when it was done. Without a due stamp, a task is due on the earliest date it or an ancestor links (never the created link) or on the daily page it sits on, and it also carries its ancestors' page links. In Write, Source, and embedded excerpts, Cmd-Enter (Ctrl-Enter elsewhere) completes the task at the caret, reopens a done one, or makes the list item, paragraph, or empty line a task stamped with today; Cmd-Shift-Enter cycles Inbox, Next, Waiting, Someday and reopens a done task into Inbox. With a selection, both make every selected paragraph line and list item a task, or change every selected task. Each is one undo step that keeps block IDs; code, headings, and front matter refuse with a notice. Dates come from an injected clock and time zone (`quire::tasks::TaskContext`). Regenerate the 224-page differential vectors with `TZ=UTC bun tools/task-vectors.ts`; the core and the native analyzer must match them.

Focusing the editor in the containing block reveals the link syntax for editing; Source exposes all syntax. Rich labels, images, reference links, and other destinations currently retain their source presentation. Internal notebook navigation remains unfinished. Headless tests intercept URL requests; native browser and accessibility acceptance remain open.

`quire_core` provides shared page-name validation, logical relative-link paths, and frontmatter boundaries. Its metadata tests compare 640 fixtures from the frozen TypeScript module; regenerate them with `bun tools/metadata-vectors.ts`. Native boundaries use UTF-8 byte offsets and are compared explicitly with the oracle's UTF-16 offsets. The editor scans frontmatter through borrowed rope characters, stopping at the delimiter without allocating a page or line string. New-page names follow the legacy trimming, NFC, length, and reserved-name rules; existing paths and text remain untouched. Logical link resolution decodes URI escapes and rejects traversal above the vault, while filesystem adapters still need to enforce notebook boundaries. Page creation and notebook navigation have yet to use these helpers.

The core's `page_title` and `frontmatter_tags` match 725 additional fixtures from the frozen module. Regenerate them with `bun tools/frontmatter-vectors.ts`; Bun and Node produce identical fixture bytes. Titles retain JSON number/array/object behavior, raw quoting, fallback filenames, and lone-surrogate escapes. `page_title` returns `JsString`, exposing UTF-16 units and an optional native UTF-8 view instead of replacing unrepresentable characters. Tags preserve the legacy inline/list forms, order, and duplicates. These helpers parse data without executing notebook content; notebook title/tag UI integration remains pending.

The core also provides daily title/path formatting, date recognition, layout detection, and settings validation. `DailyParser` retains compiled patterns and an explicit `DailyCalendar` per notebook; no active layout or clock is global. Calendar lookup belongs in background startup. Regenerate its 4,831 frozen-oracle cases with `TZ=UTC bun tools/daily-vectors.ts`, and eight isolated Node timezone/clock groups with `bun tools/daily-timezone-vectors.ts`. These include skipped civil days and daylight-saving boundaries. Invalid native calendar dates cannot become paths, and unsupported settings remain read-only.

`references(text, code_ranges)` extracts native page, block, embed, and PDF reference records with byte ranges. Callers must supply code exclusions from their current Markdown parse; the helper adds frontmatter exclusion. It preserves raw targets/labels, PDF precedence, first-match behavior, and the legacy check of each match's start. Exclusion ranges are sorted and merged once for lookup. Tests compare 559 raw/editor fixture pairs with explicit UTF-16 offset translation; regenerate them with `bun tools/reference-vectors.ts`. Node and Bun generate identical fixture bytes. Native grammar-derived exclusions and notebook navigation remain separate work.

The `test:vim-search`, `test:vim-command`, and `test:vim-mark` scripts run copied regressions, including comparisons with Neovim. They require `nvim` on PATH and enable Quire's embedded-asset policy so tests load the copied settings and queries.

`quire_store` contains the format 1 codec. Its tests read Node-generated files, ask Node to read native files, and compare seeded number and Unicode serialization. The shared `quire_core::json` representation preserves unknown fields and unpaired UTF-16 surrogates; storage retains its existing `quire_store::sync::json` import path through a re-export. Parsing, cloning, serialization, and destruction handle deep records without recursive traversal. `JsString::as_bytes` returns WTF-8, while `as_str` returns a native UTF-8 string only when the value is representable. Regenerate protocol fixtures with `node tools/protocol-vectors.ts`.

The storage library reuses Zed's `sqlez` with a fallible file-open path, WAL/FULL, FTS5, and macOS fullfsync. SQLite is pinned to bundled 3.54.1. Notebook identity/schema checks protect existing databases. Saves commit revisions, heads, outbox entries, and matching recovery changes together. A bounded worker keeps SQLite and publication I/O off its caller's thread. A save replaces an unpublished revision only when it is this device's single current head with exactly one parent and publication is certain; a page's first version and every merge stay, because another computer can create the identical revision and build on it. The attachment cache verifies content hashes and synchronizes files before registering them. Tests cover full-disk failure, rollback, stale editor versions, and process-kill recovery.

`NotebookStore::publish_to` publishes one frozen batch to an existing format 1 notebook folder. It delivers verified attachments first, preserves immutable files, and adopts a matching pending batch after interruption. Conflicting writer sequences, unexpected own batches, changed notebook identities, and incomplete files leave local revisions pending. Publication acknowledges the local folder; peer delivery and power-loss durability need separate acceptance checks.

`NotebookStore::import_batch` applies an incoming graph and cursor atomically. It leaves competing heads in place; the rescan that called it merges them afterwards. Missing parents and sequence gaps wait; malformed graphs and forks preserve local data. Imported wire records retain unknown fields and lone surrogates. Own frozen publications remain with the publisher for durable acknowledgment. Both operations run through the bounded worker.

`NotebookStore::rescan` discovers delivered device chains, retries parent dependencies, and streams requested attachments into the verified local cache. Count and payload budgets return continuations across devices and attachment names; one oversized item can proceed alone in each phase. Partial delivery and writer forks leave source files unchanged. Rescans can adopt an observed frozen publication while retaining later local saves. After a complete graph pass that reconciles this device's own log, a rescan merges every page that still has competing heads in one transaction and reports the merges in `RescanReport::merged`. Batches commit independently, so a later storage error can leave an imported prefix; callers must refresh mounted pages after errors as well as successful reports. Directory discovery currently enumerates filename metadata. The full mixed-runtime convergence schedules, checkpoints/status, watcher lifecycle, Windows synchronization, and editor integration remain unfinished.

Competing heads merge deterministically, matching `rt` 0.9.57 and its Go terminal app byte for byte. `quire_core::merge::merge_text` ports `src/core/merge.ts`: a three-way line merge against the newest common ancestor, word by word where both sides changed one line, keeping both versions (older head first, without a repeated block ID) only where the same words changed. It works on UTF-16 code units, so lone surrogates merge unchanged. A save that leaves several heads merges inside its own transaction and returns the merge with its overlap count. Merge revisions carry this device and the save time or the store clock (`open_with_clock` injects one), but their IDs depend only on content, so two computers merging the same heads produce the same ID. An edit outlives a deletion, and of two moves the newer wins. Rescans merge after the whole graph pass rather than inside each batch, as `rt` does, and only once the rescan has reconciled this device's own log: a merge in the outbox would make the importer refuse this device's own later batches during a rebuild. For the same reason opening a store does not merge, unlike `rt`; the first reconciled rescan merges heads kept by older builds or left by a crash between an import and its merge. Each page merges under its own savepoint, so a page whose merge fails keeps its heads and appears in the rescan problems. Merges never require their attachments locally, but publication still does, so a merge that references an undelivered attachment waits to publish until it arrives. Generate the differential vectors with `bun tools/merge-vectors.ts`.

Schema 2 retains attachment requests and known batch hashes across restart. Requests clear with a verified attachment's catalog commit; historical hashes detect older writer forks. Schema 1 upgrades atomically while preserving drafts, local revisions, pending publication, and the attachment catalog. The one-time upgrade reads legacy bodies individually through pages of 128 IDs to reconstruct dependencies. Migrated hash history starts at recorded cursors; unavailable earlier hashes remain unknown. Routine metadata queries use bounded pages without reading page bodies.

Schema 3 prevents coalescing a local pending revision after it appears in an imported peer batch. Since `rt` 0.9.57, an import removes every unselected outbox entry that the batch already publishes, from any device, because two computers can create the identical revision and others may build on it. A frozen selection keeps its exact bytes and records the observation with the imported cursor. Neither path changes local revision provenance. Upgrades from schemas 1 and 2 conservatively protect all existing pending revisions because those databases did not record peer observation. This prevents future deletion; it cannot reconstruct a revision already removed by an older build.

Schema 4 adds checksummed, versioned title metadata. Save/import transactions update it with the revision, and coalescing removes obsolete rows through foreign keys. A schema-3 upgrade reads current heads one body at a time through pages of 128 IDs; unrelated history stays on demand. The additive schema and backfill commit together. Older attachment upgrades retain their separate historical-body pass.

`page_metadata` returns selected heads in canonical page-identity order, including conflicts and tombstones. It limits both rows and encoded payload bytes, allowing one oversized row to progress alone. SQLite checks byte lengths before loading title payloads, and routine reads never load revision bodies. Titles follow the editor's normalized line breaks while keeping stored text and raw UTF-16 strings unchanged. Generate the 1,080 raw/editor title vectors with `bun tools/lossless-title-vectors.ts`. Missing, damaged, or outdated derived rows report a rebuild error; `rebuild_metadata` runs through the worker and rolls back if a required head is unreadable. Recovery/live-query overlays, filtered title/date lookups, and native query UI remain pending.

The query index is a separate, disposable `query-index.sqlite` beside the notebook database. Its own worker thread opens it with the notebook attached read-only, so index work never waits behind saves and never writes notes. A catalogue of selected live heads comes from checksummed title metadata without reading bodies. The app then analyzes each unanalyzed head on the background executor with the editor's own block, reference, and tag code, through a detached Zed snapshot, and stores rows keyed by immutable revision ID. Queries mirror the reference store: `find_page` (exact name, then a unique title, then a date), `backlinks` (by name or title, owned date links, and resolving block references), `mentions`, `resolve_block`, `tagged_blocks`, and `tag_names`, ordered with ICU root collation as `localeCompare` orders them. A damaged file, another notebook's index, or a new format or analyzer version is deleted and rebuilt. The window shows pages left to index and any index error; editing never depends on it. Generate the 1,254 analysis vectors with `bun tools/page-index-vectors.ts`; native blocks, links, and tags must match the reference on every one, from fresh and incrementally edited buffers. `search` mirrors the reference `SearchIndex`: an FTS5 `unicode61` table with a title row per page and a row per block, terms from `[\p{L}\p{N}_-]+` joined as required prefixes, bm25 order, 24-token snippets, and 40 results. Search rows leave with their page through a foreign-key cascade and delete trigger. Generate its 33-query oracle with `bun tools/search-vectors.ts`. One deliberate difference: the reference indexes raw disk text, so CRLF pages keep carriage returns inside snippets; the native index uses the editor's normalized text. Open pages shadow their committed rows: after typing pauses for 150 ms, the page's live text is analyzed in the background and stored in TEMP tables on the index connection, and lookups read views that drop the page's committed rows while it is open, so a page never counts twice. A closed page keeps its overlay until the index has analyzed its last committed head, so it never disappears between a save and its analysis. Search stays committed-only, as in the reference, whose index reads saved files. `with_generation` returns a query together with a generation that moves whenever committed rows, analysis, or overlays change, so callers can drop stale results.

Linked references come from `linked_references`: each referring block once, daily pages newest (or oldest) first and other pages by path, with the context that filters read (the block, its parents and children, and its page's title, links, and tags, front matter tags included). `quire_core::reference_filter` parses `#tag`, `[[Page]]`, `project:Name`, words, and quoted words, each negatable with `-`; `filter_names` resolves page and project terms and `reference_facets` ranks one-click suggestions. All 17 cases of the shared `tests/fixtures/reference-filters.json`, copied unchanged from rt and also run by its terminal app, pass through the production analyzer and index. The window's Linked references panel drives them.

Bulk tag edits plan in `quire_core::tag_edits`: rename moves each chosen tag and the tags nested under it, delete removes only the chosen tags, and both rewrite front matter `tags` in the form the page uses. The index narrows the work to pages whose tag keys the edit touches, and the editor analyzer supplies the tag tokens, so tags in code and links stay. Applying writes every changed page or none: open pages save their typing first and hold further saves, a page changed since the preview refuses the whole edit, and open pages then take in their new version. The Tags browser drives it.

The library's offline `rollback_schema_upgrade` consumes its store handle and restores schema 1 only when the added metadata is reconstructable from existing cursors, no attachment requests remain, and peer-observed saves are durably published or already frozen for publication. It refuses a rollback that would lose those protections. Stop storage workers before using this maintenance operation; normal opening only upgrades.

`CARGO_HOME=/private/tmp/quire-cargo bun run test:sync-schedules` runs 10,000 seeds with native replicas and again with a native office among frozen TypeScript replicas. Use `--from 123 --count 1 --runtime mixed` to replay a seed. `--runtime alternating` runs one schedule per seed, choosing native peers on even seeds and mixed peers on odd seeds. Each schedule uses 60 actions by default; `--steps` changes that count. The runner builds a persistent native probe, uses real SQLite databases and independently delivered folder views, and checks saved contents, ancestry, unpublished saves, and converged heads. Twelve additional cases cover delayed attachments across runtimes, a frozen publication followed by another save and reopen, a stale save merged with a tombstone, independent merges reaching one revision ID in both mixed directions, a save made while a batch is published, a TypeScript computer reading back a revision it forgot, and copied writer identities. The scheduler follows `rt` 0.9.57: stale saves continue from their merge, settling runs up to 12 rounds, and a computer left with competing heads fails the schedule. Progress includes completed counts; failures retain the fixture and JSON request trace and print a replay command. This Unix FIFO harness runs on macOS/Linux and keeps WAL/FULL storage policy. Provider placeholders become invalid empty files in the native folder mirror, so their import diagnostics can differ from the TypeScript reader's unavailable content. It does not establish Windows, real provider, power-loss, or release performance acceptance.
